# TOP RIDE — перенос ВСЕХ данных с локального компьютера на Vercel

Для владельца TOP RIDE. Важно: переносится **вся PostgreSQL**, включая
снаряжение, клиентов, брони, платежи, историю операций и учётные записи.
Файлы `exported_clients_*.csv` и `exported_inventories_*.csv` не подходят
для полного переноса: в них нет финансовой истории.

## До начала

- На компьютере установлен **Docker Desktop** и запущена старая локальная
  PostgreSQL. Проверить: `docker compose ps`.
- В файле `.env` указан **только локальный** `DATABASE_URL` с
  `localhost`/`127.0.0.1`. Не заменяйте его адресом Vercel.
- В Vercel создана Prisma Postgres, доступ к **Production** подключён.
- Перед переносом перестаньте добавлять/редактировать данные в локальной CRM.
- Целевая Prisma Postgres должна быть **пустой**. Если ранее выполнили
  `npm run db:setup` на облаке и таблицы уже существуют, скрипт остановится.
  **Не удаляйте** таблицы самостоятельно: свяжитесь с разработчиком.
- Весь перенос делается **только из папки проекта на вашем Windows ПК**.
  ChatGPT/GitHub/Vercel не видят содержимое вашей локальной PostgreSQL.

## 1. Получить актуальный код и создать бэкап

В PowerShell (из своего проекта):

```powershell
cd C:\Users\sasha\ski-rental-crm
git switch main
git pull --ff-only origin main
npm ci
docker compose ps
npm run db:backup:local
```

Скрипт создаёт **полный** PostgreSQL архив в приватной папке
`.topride-private-backups\topride-full-....dump`. Он проверяет содержимое
архива с помощью `pg_restore --list` и **ничего не удаляет** из старой базы.
Никогда не отправляйте этот файл на GitHub или в публичный чат.

Если Docker Desktop не запущен или `.env` содержит не локальный
`DATABASE_URL`, остановитесь и исправьте источник: иначе можно скопировать
не те данные.

## 2. Привязать проект Vercel

Установите/запустите CLI в папке проекта:

```powershell
npx vercel link
```

Выберите **existing project** `ski-rental-crm` в правильной команде.
Не создавайте новый проект.

## 3. Восстановить архив в пустую Production PostgreSQL

Подставьте **точное имя файла**, выведенное на шаге 1:

```powershell
npx vercel env run -e production -- npm run db:restore:vercel -- .topride-private-backups\topride-full-2026-11-05T00-00-00-000Z.dump
```

Это **пример имени файла**: замените на своё.
Команда проверяет, что облако — это прямое подключение к `db.prisma.io`,
что указан адрес TOP RIDE и что в облачном `public` нет таблиц.
Показывает **только количество** клиентов, инвентаря, броней и платежей.
Если всё совпадает, введите в PowerShell:

```text
RESTORE TOP RIDE
```

Данные импортируются **одной транзакцией**, поэтому частичной записи при
ошибке PostgreSQL не будет. Оригинальная локальная БД и резервная копия
остаются нетронутыми.

**Не запускайте `prisma migrate reset` или `pg_restore --clean`.**

## 4. Проверить количество данных и применить недостающие миграции

```powershell
npx vercel env run -e production -- npm run db:verify:vercel
npx vercel env run -e production -- npm run db:setup
npx vercel env run -e production -- npm run db:doctor
```

Все строки таблиц (клиенты, инвентарь, брони, платежи, пользователи,
журналы, настройки) должны показывать `OK` и одинаковые количества.
При `DIFF` остановитесь и сохраните вывод без персональных данных и паролей.
После восстановления миграция `db:setup` применяет **только недостающие**
миграции Prisma, без сброса данных.

## 5. Настроить единственный аккаунт владельца

Если миграция и диагностика успешны:

```powershell
npx vercel env run -e production -- npm run owner:setup -- YOUR_EMAIL
```

Замените `YOUR_EMAIL` на ваш адрес. Скрипт спросит **пароль в терминале**:
символы не показываются и пароль **не сохраняется в GitHub/Vercel env**.
Лучше выбрать уникальный пароль длиной от 16 символов, а не простую
комбинацию типа `qwerty123456`. При подтверждении `SET OWNER`
существующий пользователь с таким email будет обновлён, иначе создан.
У остальных пользователей доступ блокируется (не удаляются их записи и
история), а старые сеансы аннулируются. Новый пароль сохраняется только
в виде хеша Better Auth.

Не запускайте команду до полной проверки переноса.

## 6. Проверить сайт

- Откройте адрес Production, настроенный в `BETTER_AUTH_URL`, например
  `https://ski-rental-crm-aicangeneratecodes-projects.vercel.app/login`.
- Войдите по своему email и новому паролю.
- Проверьте снаряжение, клиентов, брони, историю платежей и аналитику.
- Создайте **одну тестовую бронь**, проверьте сценарий оплаты, возврата и
  редактирования и убедитесь, что данные сохраняются после перезагрузки.
- Убедитесь в включённом резервном копировании **облачной** PostgreSQL
  и выполните тестовое восстановление на отдельную базу перед сезоном.
- **Не удаляйте локальную PostgreSQL** до полной проверки и независимого
  бэкапа облачной базы.

## Как интерпретировать ошибки

- `Cloud already contains tables` — целевая БД не пустая. Ничего не удаляйте.
- `Source database appears empty` — выбран не тот локальный `.env` или
  база пока не содержит снаряжения/клиентов/броней.
- `File missing / archive incomplete` — создайте новую резервную копию.
- `Docker unavailable` — запустите Docker Desktop.
- `Wrong production environment` — проверьте `vercel link` и целевую
  команду/проект Vercel.
- `pg_restore` error — одна транзакция откатывает изменения; **не**
  используйте опасные флаги очистки, сохраните текст ошибки.
- `DIFF` после `db:verify:vercel` — обратитесь за разбором до создания
  продуктивных записей.

**Не присылайте DATABASE_URL, пароли, токены и полный архив базы в чат.**
