# TOP RIDE — этапный план развития

Утверждено 5 ноября 2026 года.

## Исключения по решению владельца
Не реализуем в этой дорожной карте:
- разграничение прав сотрудников;
- отдельный учёт залогов;
- частичный возврат внутри одной аренды.

Текущая модель единой авторизованной сессии остаётся без изменений. Не объявляйте её ролевой моделью.

### Изменения по решению владельца
- [x] QR-коды и все маршруты их печати удалены из системы.
- [x] Архивные завершённые/отменённые брони можно удалить окончательно через корзину с подтверждением. При этом удаляются связанные платежи и журнал действий аренды; состояние обслуживания снаряжения сохраняется. Действие не отменяется.

Этап 4 не требует новой миграции. Но при обновлении с более старых веток
должны быть применены миграции этапов 1–3 после резервного копирования БД.

## Этап 5. Деньги, документы и администрирование
- [x] Отчёты по фактическим платежам и возвратам с часовым поясом Europe/Belgrade, разбивкой по способам оплаты, динамикой, расчётной загрузкой и популярностью оборудования; CSV для Excel.
- [ ] PDF-договоры **не реализуем сейчас** по решению владельца: отдельная работа после согласования всех требований.
- [x] Реальные тарифы в PostgreSQL с версиями, журналом изменений и подтверждаемой синхронизацией доступного инвентаря; сохраняемые контактные данные и название компании. Исторические брони/платежи не пересчитываются.
- [x] Серверные фильтры и курсорная пагинация **журнала платежей** (50 записей), индексы отчётов, постраничный каталог оборудования (20/50/100 после сортировки). **Не выполнено:** серверная пагинация основного списка клиентов и аренд — эти страницы пока загружают все записи.
- [x] Раннее применение темы до отрисовки, TOP RIDE в заголовках страниц и единый стиль новых отчётов. Проверка на реальных браузерах/устройствах ещё нужна.

### Особенности этапа 5

- В `/reports` можно выбирать период до 366 дней, скачивать CSV и видеть поступления минус возвраты. День платежа рассчитывается в Europe/Belgrade; будущая бронь без оплаты **не считается полученным доходом**.
- `/reports/ledger` показывает журнал платежей и возвратов с фильтрами и курсорной пагинацией по 50 записей. Последовательность подтверждена интеграционным тестом на PostgreSQL с 52 записями.
- Чистые поступления — **движение денег**, не бухгалтерская прибыль и не начисленная выручка.
- Загрузка снаряжения расчётная, по запланированным датам (включая забронированные дни). Вместимость берётся из **текущего** неархивного каталога, поэтому загрузка прошлых сезонов — оценка.
- При окончательном удалении архивной брони связанные платежи удаляются по решению владельца и больше не попадают в отчёты. Перед массовым удалением следует сохранить независимую бухгалтерскую выгрузку.
- Новая миграция: `prisma/migrations/20261105190000_phase5_reporting_settings_indexes`. Требуется проверенная резервная копия PostgreSQL и правильный `DATABASE_URL` перед `npm run db:setup`.
- GitHub Actions проверяет типы, lint, отчёты, миграции и сценарии на **временной** PostgreSQL, но не проверяет рабочую БД пользователя и взаимодействие в браузере. Ручная проверка и пробное восстановление бэкапа остаются необходимыми.

## Работа с БД после первого этапа

Новая миграция: `prisma/migrations/20261105160000_booking_archive`.

Перед её применением к рабочей БД создайте резервную копию и проверьте `DATABASE_URL`.
Далее `npm run db:setup` применяет новую колонку `Booking.archivedAt` и типы событий.
Не используйте `prisma migrate reset` на существующей базе.

Изменения в коде и зеленая CI-проверка не гарантируют, что локальная БД пользователя уже обновлена.
