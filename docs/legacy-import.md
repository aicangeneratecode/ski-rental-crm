# TOP RIDE — безопасный импорт клиентов и инвентаря

Этот инструмент импортирует **только** имена, телефоны, email, примечания
и оборудование. Долги, старые платежи, старые статусы «В аренде»,
покупные цены, залоги и паспортные данные не импортируются.

**Важно:** файл JSON содержит персональные данные клиентов. Не добавляйте
его в Git, не загружайте в публичный репозиторий. Путь `imports/` добавлен
в `.gitignore`.

## 1. Получите очищенный JSON

Скачайте `topride_import_clean_2026-11-04.json` из чата и сохраните на ПК.
Исходные CSV для этого инструмента не нужны; они обработаны отдельно.
В подготовленном файле 443 клиента и 136 единиц инвентаря.

## 2. Проверка без базы

Из папки проекта выполните:

```powershell
npm install
npm run import:legacy -- --file "C:\Users\sasha\Downloads\topride_import_clean_2026-11-04.json" --validate-only
```

Исправьте путь, если файл скачан в другую папку. Эта команда не обращается к
базе данных и ничего не создаёт.

## 3. Сверка с базой (без изменений)

Убедитесь, что в `.env` настроен `DATABASE_URL` той базы, в которую
**действительно** хотите импортировать данные:

```powershell
npm run import:legacy -- --file "C:\Users\sasha\Downloads\topride_import_clean_2026-11-04.json"
```

Появится количество новых, уже существующих и нераспознанных записей.
По умолчанию это **dry run**: в базе ничего не меняется.
Ранее существующие клиенты и оборудование сопоставляются по имени и
телефону либо имени, тарифу и размеру, без перезаписи данных.
Повторный запуск с тем же файлом не должен создавать те же записи второй раз.

## 4. Перед настоящим импортом

Создайте резервную копию базы через интерфейс провайдера PostgreSQL или
`pg_dump` — особенно если это рабочая база с текущими бронями.

Выгрузка содержит **одну позицию без категории**:
`HIGHLANDER black M`. Она остаётся в JSON, но не импортируется, пока не
будет присвоен реальный тариф. Отдельно проверьте 13 позиций без
определённого размера — вместо выдуманного размера указано «Не указан».

Если знаете тариф для HIGHLANDER, в JSON найдите запись
`"sourceRow": 135`, заполните `tariff` одним из кодов
`src/lib/equipment/tariffs.ts` и `dailyRate` актуальной ценой
в целых динарах; тогда загрузятся все 136 позиций. Не назначайте тариф
наугад.

В подготовленном JSON стоимость аренды оборудования взята из текущих
тарифных пресетов проекта; сверьте их перед импортом.

## 5. Запуск записи в базу

```powershell
npm run import:legacy -- --file "C:\Users\sasha\Downloads\topride_import_clean_2026-11-04.json" --apply
```

Скрипт создаёт **только новые** записи одной транзакцией. Ничего не
удаляет и не изменяет в существующих строках. Для новых единиц инвентаря
устанавливается статус `READY` («Свободен»), независимо от прежнего
статуса в старой системе; статус существующего оборудования не сбрасывается
и действующие брони остаются неизменными.

Если товар действительно занят сейчас, проверяйте это в новой CRM
перед выдачей. Старые аренды, даты выдачи и платежи в этих двух CSV
отсутствуют и не импортируются.

## 6. Проверка результата

Откройте:
- http://localhost:3000/customers
- http://localhost:3000/equipment

Если программа нашла ранее существующие записи, добавленных строк будет
меньше, чем в файле — это нормально. Подробная сводка появится перед записью.
