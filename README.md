# Ski Rental CRM

CRM горнолыжного проката на Next.js, TailAdmin Free (MIT), PostgreSQL и Prisma 7. Интерфейс — русский, валюта — RSD.

## Что работает

- Создание и редактирование отдельных единиц оборудования.
- Поиск по номеру, модели, размеру; фильтры по категории и состоянию.
- Состояния: готово к выдаче, обслуживание, архив. Восстановление — через редактирование архивной карточки.
- Базовые тарифы из прайса и индивидуальная цена предмета. Справочник тарифов — в Настройках.
- Уникальность инвентарного номера и защита от потери параллельных изменений.
- Данные сохраняются в PostgreSQL, не в localStorage.

Брони, расчёт дней, оплаты и авторизация сотрудников — следующие этапы. Готовность оборудования не означает доступность на конкретные даты. Палки и крепления сохраняют обычную цену 250 RSD; бесплатность в комплекте и скидки будут включаться вручную в брони. Цена чехла не задана: сотрудник должен ввести её явно.

## Требования

Node.js 24 LTS (минимум для этого проекта — 22.12). Для основного варианта локальной базы нужен запущенный Docker Desktop. Альтернатива без Docker приведена ниже.

## Быстрый запуск в Windows / PowerShell

Из папки проекта, после обновления ветки:

```powershell
npm ci
if (!(Test-Path .env)) { Copy-Item .env.example .env }
docker compose up -d --wait
npm run db:setup
npm run dev
```

Открыть http://localhost:3000/equipment. `npm ci` генерирует Prisma Client автоматически. Скрипт `db:setup` применяет только ожидающие миграции и не очищает таблицы. Повторный запуск безопасен.

`compose.yaml` запускает PostgreSQL на 127.0.0.1:5432. Пример пароля предназначен только для локальной базы. Если этот порт уже занят, используйте другую базу или измените одновременно порт в compose.yaml и DATABASE_URL.

## Без Docker

В отдельном терминале:

```powershell
npm run db:local
```

Prisma Dev запускает локальную PostgreSQL-совместимую базу. Скопируйте выведенную обычную строку `postgres://` или `postgresql://` в `DATABASE_URL` файла `.env` (не `prisma+postgres://`). Оставьте терминал базы открытым. Во втором терминале:

```powershell
npm run db:setup
npm run dev
```

Можно использовать и уже существующий PostgreSQL: достаточно его DATABASE_URL и `npm run db:setup`.

## Сохранность данных

Docker хранит данные в именованном томе `rental_postgres`. `docker compose stop` останавливает базу, не удаляя данные. Не выполняйте `docker compose down -v`, если хотите сохранить каталог. Файлы `.env` не должны попадать в Git. При изменении `.env` перезапустите Next.js.

Для проверки: добавьте предмет, обновите страницу, перезапустите приложение — карточка должна остаться. Затем проверьте редактирование, архив и восстановление через фильтр «В архиве».

## Проверки

```powershell
npm test
npm run lint
npm run build
npm run test:db
```

`test:db` требует DATABASE_URL и применённой миграции. Он создаёт временную запись с уникальным TEST-номером, проверяет сохранение, дубликаты, параллельные изменения, архив и восстановление; затем удаляет только собственную тестовую запись. Без DATABASE_URL тест пропускается.

## Развёртывание

Текущий этап предназначен для локальной работы через `npm run dev`. В production запись серверными действиями закрыта до подключения авторизации сотрудников; `npm run start` позволяет проверить режим просмотра. Не открывайте dev-сервер в интернет. Перед общей работой 2–3 сотрудников нужно подключить вход и роли, общую PostgreSQL и резервное копирование.

## Обновление CRM на Vercel

`vercel.json` запускает генерацию Prisma, `prisma migrate deploy`, затем сборку Next.js. Миграции добавляют таблицы без сброса базы. Production должен использовать production DATABASE_URL; Preview — отдельную тестовую базу. Не направляйте Preview на production-базу.

Для развёртывания нужны DATABASE_URL, BETTER_AUTH_SECRET и BETTER_AUTH_URL (URL рабочего сайта). Секреты задаются в Vercel, не в Git. В настройках Git выберите нужную Production Branch; текущая разработка находится в feat/crm-layout.

История записывает новые действия после применения миграции booking_events. Для старых броней показываются сохранённые метаданные создания; прошлые смены статуса не восстанавливаются.

Локально после получения кода: npm ci, npm run db:setup, npm run db:generate, npm run dev. db:setup применяет миграции к базе из локального DATABASE_URL.


## Если не работают выдача, возврат, платежи или удаление

Открывающиеся страницы **не гарантируют**, что все новые таблицы существуют. В частности, выдача и возврат пишут журнал действий в таблицу `BookingEvent`; платежи пишутся в таблицу `Payment`. Если после `git pull` не запускать миграции, операции могут возвращать ошибку.

На Windows, в терминале проекта:

```powershell
git switch design/top-ride-premium
git pull --ff-only origin design/top-ride-premium
npm ci
npm run db:doctor
npm run db:setup
npm run db:doctor
npm run dev
```

`db:doctor` безопасен: только проверяет подключение, наличие основных таблиц, режим read-only и запросы внутри транзакции. Ничего не записывает. `db:setup` — это `prisma migrate deploy`, применяет ожидающие миграции к базе из `.env`, **не удаляя существующие записи**. Убедитесь, что `DATABASE_URL` в `.env` указывает именно на нужную базу; не публикуйте эту строку.

Если вместо `BookingEvent` или `Payment` показано `MISSING`, после успешной миграции эти таблицы должны появиться. Если `db:setup` сообщает о конфликте или неудавшейся миграции, **не сбрасывайте базу** и не запускайте `prisma migrate reset`: сохраните журнал команды, передайте его разработчику и сделайте резервную копию.

Если `db:doctor` показывает всё `OK`, но изменения по-прежнему не проходят, посмотрите в терминале с `npm run dev` строку вида `[TOP RIDE database] { operation, name, code }` и передайте **только код и название операции**, без секретов или персональных данных. Это позволяет определить следующую причину без угадывания.


## Безопасный архив завершённых аренд (этап 1)

В TOP RIDE удаление завершённых и отменённых броней **заменено на архивирование**.
Оно не удаляет платежи, оборудование и журнал действий: запись скрывается
из обычного рабочего списка, но доступна во вкладке «Архив» и может быть восстановлена.
Для архивирования/восстановления требуется подтверждение.
Аренды со статусом «Забронировано» или «Выдано» архивировать нельзя.

Чтобы установить эту версию локально:

1. **Создайте резервную копию PostgreSQL** через провайдера или `pg_dump`.
   Убедитесь, что файл копии пригоден для восстановления.
2. Проверьте локальный `DATABASE_URL` в `.env` — он должен указывать на нужную базу.
3. После `git pull` выполните:

```powershell
npm ci
npm run db:setup
npm run db:doctor
npm run dev
```

4. Проверьте «Аренды» → «Завершённые» → «В архив»,
   затем «Аренды» → «Архив» → «Восстановить» на тестовой записи.

Миграция `20261105160000_booking_archive` добавляет поле `Booking.archivedAt`
и события аудита `ARCHIVED` / `RESTORED`. Она не сбрасывает базу и не удаляет
существующие записи. **Не запускайте `prisma migrate reset` на рабочей базе.**

GitHub Actions использует отдельную временную PostgreSQL, применяет миграции
и тестирует создание, выдачу, оплату, возврат, архивирование и восстановление.
Это не заменяет проверку пользовательских форм в браузере.

Дорожная карта: `docs/top-ride-roadmap.md`.

## Этап 2 — изменение и продление существующих аренд

Из карточки и списка аренд доступны «Редактировать» (для брони до выдачи) и «Продлить».
До выдачи можно изменить клиента, даты, инвентарь, скидку, примечания.
После выдачи доступны только продление даты возврата, скидка и примечания.
Сервер проверяет занятость конкретных предметов и защищает уже внесённые платежи;
если новая стоимость стала ниже полученной оплаты, сначала оформите возврат разницы.
Ставка выбранного ранее предмета сохраняется по условиям этой брони; новые предметы
добавляются по их актуальной ставке. История изменений хранится в журнале.

Досрочная выдача возможна на **один день** раньше начала аренды с обязательной
причиной (8–500 символов), когда в день досрочной выдачи инвентарь свободен.
В карточке выдачи доступно поле причины; она сохраняется в журнале действий.

В форме бронирования доступны шаблоны комплектов для ускорения выбора категорий.
Размеры и конкретные экземпляры выбирает сотрудник — произвольное автоматическое
назначение размера отключено.

После создания резервной копии PostgreSQL и проверки локального DATABASE_URL:

```powershell
git switch design/top-ride-premium
git pull --ff-only origin design/top-ride-premium
npm ci
npm run db:setup
npm run db:doctor
npm run dev
```

Миграция `20261105171000_booking_edits` добавляет виды событий UPDATED/EXTENDED
и текст описания изменений в BookingEvent. Рабочую базу она не очищает.
Не запускайте `prisma migrate reset` на рабочей базе.

CI использует только временную PostgreSQL, но пользовательские формы и работа
с локальной базой требуют отдельной проверки.


## Этап 3 — инвентарь и клиенты

- При выдаче и возврате в карточку предмета добавляются события с датой, сотрудником и номером аренды.
- После возврата статус оборудования становится `MAINTENANCE`. До следующей выдачи проведите осмотр:
  Оборудование → предмет → Обслуживание → тип «Осмотр», состояние «Исправно» → «Записать осмотр».
- Если выявлено повреждение, выберите «Повреждение» либо «Требуется обслуживание»: предмет останется недоступным.
- В карточке клиента: «Повторная бронь» открывает новую аренду с клиентом и доступным
  оборудованием из прошлой аренды. Период и скидку нужно указать заново.
- «Объединить дубликат» выбирает основной профиль и переносит все аренды с оплатами
  в одну карточку. Старый профиль остаётся скрытым архивным псевдонимом,
  записи объединения и изменения каждой брони сохраняются для аудита.

**Перед применением**: создайте проверяемую резервную копию PostgreSQL, проверьте
`DATABASE_URL`, затем выполните `npm ci`, `npm run db:setup`, `npm run db:doctor`
и `npm run dev`. Новая миграция:
`prisma/migrations/20261105175000_equipment_maintenance_customer_merges`.
Она не удаляет существующие записи. На рабочей базе **не запускайте** `prisma migrate reset`.

При первом включении не требуется осматривать всю старую базу автоматически;
только предметы, возвращённые через новую версию CRM, переходят в ожидание осмотра.
После миграции проверьте браузерные формы на тестовой записи.
